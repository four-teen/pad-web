# Office Document Router

`index.js` provides the uniform office dashboard, queues, document registration, timeline, and movement dialogs.

The sidebar groups tasks into **Document Preparation** (Register document, My Document), **Receipt & Routing** (Awaiting Receipt, Received, Outgoing, Returned), **Review & Action** (For Approval for PAD; For Action for Central Records), and **Completed & History** (Acted, Delivered / completed, All Timeline). Review & Action is hidden for roles without one of these queues. Central Records uses Awaiting Receipt before confirming a PAD handoff, then For Action. Its redundant Returned from PAD menu/card is removed. Old `pad_results` frontend links open Awaiting Receipt.

Unsent registrations from the encoding office appear in **My Document**, with **Send** and **Delete**. Their title opens the details/timeline. Deletion is confirmed and permitted only while no dispatch exists; consumed file codes are never recycled. Other-office handoffs remain **Received** after receipt, including a document returned to its original office. Outside intake remains Received. Registration opens the relevant queue.

The physical Incoming queue is displayed as **Awaiting Receipt**. **For Approval** and its workload card appear in OVP PAD; **For Action** and its count/card appear in OVP Central Records. Received, For Approval, and For Action use simple document cards with sending module/office, purpose or outcome, and custody badges. For Action includes all received Approved, Disapproved, and Returned for correction decisions awaiting Records action and excludes pending handoffs and already dispatched owner releases. These documents are excluded from ordinary Received and its count. Encoder, receiver and timestamps remain in View/timeline. PAD's **Record decision & return** dialog sends one selected outcome and optional/required remarks to the shared API, which derives the exact Central Records destination. Automatic PAD decision handoffs do not populate the issue-related **Returned** list or badge; explicit Return-button actions remain tracked there. Earlier decision cycles remain in details. Configure the API review schema before using this UI; see pad-api/docs/pad-review-decisions.md.

**Outgoing** lists and counts only the latest handoffs sent by the selected office and awaiting destination receipt. Once the destination confirms receipt, the document leaves the sender's Outgoing and remains accessible in **All Timeline**. A forward or return creates an Outgoing item only for that handoff's sender; earlier senders do not regain an Outgoing item. Dashboard cards and navigation counts follow the same API rule. Records retains its separate Acted archive after owner delivery.

**All Timeline** defaults to **All offices** in the active OVP PAD and OVP Central Records modules, with global sidebar/dashboard totals. Its office filter can narrow the registry; leaving All Timeline restores the ordinary working-queue scope. In ordinary office mode, All Timeline lists/counts only documents encoded or sent by that office. Receive-only documents still appear in their actual work/archive queues, including Delivered / completed, with their details/history accessible there. Registration history identifies the encoding office independently from the selected document source. Role switching clears any global filter. PAD's global timeline access does not enable outside intake or other offices' actions.

The shared application starts this module after the authenticated user selects OVP PAD, OVP Central Records, or SKSU Officials. Module navigation uses `#doc_router` and `#doc_router/{queue}`. The API client sends the selected role in `X-PAD-Role` and uses `/api/doc_router/routing/workspace` and `/api/doc_router/documents` endpoints. Office scope, permissions, numbering, and document transitions are enforced by the PAD API.

Document detail presents a compact, latest-first journey with numbered, colored milestones, alternating cards on desktop and a vertical track on phones. Original step numbers descend from the latest event on the left to registration on the right; on phones the latest event appears at the top. Latest event and First step buttons navigate longer desktop histories. Each event shows its timestamp, office handoff, and actor; Remarks & duration expands its notes, office stay, and transit information. Dates retain Asia/Manila formatting and server-based duration calculations. Document headings use uppercase Saira in vivid orange. Attachment controls, document actions, and supporting details follow the journey.

Register document loads the PAD type and personnel catalogs from `/api/doc_router/routing/registration-options`. Run `php scripts/setup-document-types.php` in `pad-api` to import the sam.pad selections before using this form. Other types offer optional personnel links; Travel Order adds required traveler, destination, purpose, date, travel type, and vehicle fields. Hidden travel fields are disabled and excluded from submissions for other types. The document view displays the saved additional information below its journey.

Run `php scripts/setup-document-sources.php` in `pad-api` to import `sam.pad.tbldivisions` into the PAD source catalog. The Document source dropdown lists these imported offices / agencies and provides in-list search, without a separate search input or a My office option. The selected source identifies the document owner; the signed-in office remains responsible for registration and routing. The particulars textarea appears in lists as the document heading when no subject is supplied. The file is uploaded later from document detail after registration.

The administration workspace reuses the same document components with its existing routes. Both workspaces use one document service, attachment store, annual number series, and history.

Rows and received-document cards show a paperclip **Attachment** button when `stored_file_name` is present. This opens the shared responsive preview modal; the timeline's attachment control opens the same preview. Images and PDFs render within PAD, with zoom/fit and PDF page controls. Word/Excel files show a file summary with an explicit Download action. Unsupported, encrypted, or damaged files can be downloaded when their bytes are available; a missing/inaccessible file shows the API error. Opening a preview never invokes a browser download.

`src/attachment-preview.js` fetches through the existing authenticated, role-scoped download endpoint and releases cached file URLs, aborts fetches, and cancels rendering on close/sign-out/role change. `src/pdf-preview.js` loads Mozilla [PDF.js](https://mozilla.github.io/pdf.js/examples/) and its bundled local worker on demand; document contents are not sent to an external viewer. No API/schema changes are required. Run `npm ci` before building after this dependency change.

Awaiting Receipt offers **View**, **Receive**, and **Return** for ordinary incoming handoffs. PAD decisions at Records offer **View** and **Receive**, using the existing standard/custom receipt remarks. After confirmation, the UI opens **For Action**, where **Act** becomes available. View opens the timeline and final-copy upload. **Act & send to owner** selects the owner and records the action taken without a repeated receipt checkbox. The API requires the prior receipt and commits Records' action and owner dispatch together, then the UI opens Acted and clears For Action, with **Acted** and **Awaiting owner receipt** displayed separately. An Act failure preserves the separately confirmed receipt. Existing attachment and latest-PAD-route notes remain required.

Acted retains Records' processing/release archive. The selected owner confirms the incoming hard copy using Receive, which records Delivered and opens Delivered / completed. Delivered means actual owner receipt; Completed means closure without a delivery handoff. Correction instructions can be resubmitted by their owner on the same file code. Earlier terminal Acted records remain closed and visible. No schema change or live-document rewrite is required.

Document loading displays a spinner and status text in queues and Overview, removes stale actions, and disables pagination until the latest response arrives. Failed loads show an inline Try again button. Searches remain debounced at 250 ms; newer refreshes abort the previous workspace request, and request generations prevent old responses from replacing newer results or surviving a role reset. Action buttons show Loading while fetching current permissions; save buttons retain their Saving state.

The active-office directory is shared for 60 seconds within the current module session, including concurrent refreshes. Office administration changes invalidate it immediately; sign-out and role changes clear it. Document lists, counts, and permissions are freshly requested on every refresh. Receive/Act/Delete redirects fetch only the destination queue; hidden table/card layouts are not rendered twice. The API builds the authorized 20-document page before loading its routing details and calculates queue counts together. Existing API installations should run `php scripts/setup-document-performance.php` in `pad-api` for the query/index tuning; new schemas already include these indexes. Use `PAD_PREVIEW_DELAY_MS=2500` when starting the isolated `tests/pad-review-preview-server.js` to inspect loading states in the browser.
